# 라인업 레이더 (모바일용)

폰에서 링크를 열면 경기 목록(양 팀 몇 군 · 오늘 전력 vs)이 뜨고, 경기를 누르면
**핵심 포인트 · 오늘 라인업 전력 비교 · 팀 에이스 · 양 팀 포메이션 · 빠진 주전 · 선수별 시즌 기록과 최근 분위기**가 나온다.
깃허브가 10분마다 대신 데이터를 받아와 페이지를 갱신한다. 서버·비용 없음, 폰은 링크만 열면 된다.

## 데이터 소스

| 종목 | 쓰는 곳 | 성격 |
|---|---|---|
| 축구 | ESPN 공개 피드 (`site.api.espn.com`) | 키 없음, 라인업·포메이션·과거 선발 기록 |
| 야구(MLB) | MLB 공식 Stats API (`statsapi.mlb.com`) | 공식, 라인업·선발투수·시즌 타석 |
| 농구(NBA) | ESPN 공개 피드 | 스타터·결장 정보 (시즌 개막 후 확인 필요) |
| A매치 전력 | World Football Elo (`eloratings.net`) | 대표팀 Elo 레이팅 (남자 대표팀) |

## 설치 (한 번만, 20~30분 · PC 권장)

### 1. 깃허브 가입
1. https://github.com 접속 → 오른쪽 위 **Sign up**
2. 이메일·비밀번호·아이디(영문) 입력 → 이메일로 온 인증 코드 입력
3. 무료 플랜(Free) 그대로 사용

> 아이디가 곧 주소가 된다. 예: 아이디 `toto123` → `https://toto123.github.io/lineup-radar/`

### 2. 저장소(repository) 만들기
1. 로그인 후 오른쪽 위 **+** → **New repository**
2. Repository name: `lineup-radar`
3. **Public** 선택 (무료로 Pages·Actions를 쓰려면 Public)
4. 나머지는 건드리지 말고 **Create repository**

### 3. 파일 올리기
1. 받은 `lineup-radar.zip`을 PC에서 압축 해제 → `lineup-radar` 폴더가 생김
2. 방금 만든 저장소 화면에서 **uploading an existing file** 링크 클릭
3. `lineup-radar` 폴더를 **열어서 안의 내용물 전부**를 선택해 브라우저 창에 끌어다 놓기
   - `lineup-radar` 폴더 자체가 아니라 그 **안의** `collect.py`, `docs`, `.github` 등을 끌어다 놓아야 함
   - 윈도우에서 `.github` 폴더가 안 보이면: 탐색기 **보기 → 표시 → 숨긴 항목** 체크
4. 아래 **Commit changes** 클릭
5. 저장소 첫 화면에 `.github`, `docs`, `collect.py`, `config.json` 등이 보이면 성공

**`docs/.nojekyll` 파일도 있어야 한다** (깃허브의 페이지 변환기를 끄는 빈 파일, 없으면 Pages 빌드가 실패할 수 있음).
없으면 **Add file → Create new file** → 이름에 `docs/.nojekyll` → 내용은 비운 채 **Commit changes**.

**`.github` 폴더가 안 올라갔을 때** (저장소 첫 화면에 `.github`가 없으면)
1. **Add file → Create new file**
2. 파일 이름 칸에 `.github/workflows/update.yml` 입력 (슬래시를 치면 폴더가 자동으로 생김)
3. PC의 `lineup-radar/.github/workflows/update.yml`을 메모장으로 열어 전체 복사 → 붙여넣기 → **Commit changes**
4. 같은 방법으로 `.github/workflows/probe.yml`도 만들기

### 4. 자동 실행 권한 주기
1. 저장소 **Settings** → 왼쪽 **Actions → General**
2. 맨 아래 **Workflow permissions** → **Read and write permissions** 선택 → **Save**
   (수집기가 결과를 저장소에 저장하려면 쓰기 권한이 필요)

### 5. 웹페이지(Pages) 켜기
1. **Settings** → 왼쪽 **Pages**
2. Source: **Deploy from a branch**
3. Branch: **main**, 폴더: **/docs** → **Save**
4. 1~2분 뒤 같은 화면 위쪽에 `Your site is live at https://아이디.github.io/lineup-radar/` 가 뜸

### 6. 첫 수집 돌리기
1. 저장소 위 메뉴 **Actions**
2. 처음이면 초록 버튼 **I understand my workflows, go ahead and enable them** 클릭
3. 왼쪽 **라인업 수집** → 오른쪽 **Run workflow** → 초록 **Run workflow**
4. 목록에 새 실행이 생기고 노란 원(진행 중) → **초록 체크(성공)** 가 되면 완료 (보통 1~5분)
5. 이후로는 **10분마다 자동**으로 돈다

### 7. 폰에서 열기
1. 폰 브라우저로 `https://아이디.github.io/lineup-radar/`
2. **홈 화면에 추가**: 아이폰 사파리 = 공유 버튼 → 홈 화면에 추가 / 안드로이드 크롬 = 메뉴(⋮) → 홈 화면에 추가
3. 라인업이 아직 안 나온 시간이면 경기 목록만 뜨고 "라인업 ○○:○○쯤 발표"로 표시되는 게 정상

### 8. 소스 점검 (한 번)
1. **Actions** → 왼쪽 **소스 점검** → **Run workflow**
2. 끝나면(초록 체크) 그 실행 클릭 → **probe** → **점검 실행** 줄을 펼치기
3. 나온 글을 전부 복사해서 Claude에게 보내기 (K리그·아시안게임·국내 리그·Elo 확인용)

## 문제가 생기면

| 증상 | 원인 / 해결 |
|---|---|
| 주소를 열면 **404** | Pages 설정(5단계) 확인. 설정 직후면 2~3분 기다린 뒤 새로고침 |
| "데이터를 불러오지 못했습니다" | 아직 수집이 한 번도 안 돈 상태. 6단계 실행 |
| Actions 실행이 **빨간 X** | 실행 클릭 → 빨간 단계 펼쳐서 내용 확인. `Permission denied`/`403`이면 4단계(쓰기 권한) |
| 목록이 오래된 채로 안 바뀜 | Actions 탭에서 최근 실행 시각 확인. 붐비는 시간엔 10분 예약이 몇 분씩 밀릴 수 있음 |
| 60일쯤 지나 자동 실행이 멈춤 | 깃허브가 오래 안 쓰인 저장소의 예약 실행을 끔. 메일이 오면 Actions 탭에서 다시 켜기 |
| 폰에서 옛 화면이 보임 | 페이지를 아래로 당겨 새로고침 (깃허브 페이지는 최대 10분 캐시) |

- 결과 데이터가 10분마다 저장소에 커밋된다 (`data: ...` 커밋). 정상이다.
- 수집 중 ESPN이 계속 응답하지 않으면 그 실행은 몇 번 시도 후 바로 멈추고 다음 차례에 다시 시도한다.

## 쓸 때 알아둘 것

- 라인업은 보통 경기 시작 1시간 전에 나온다. 그때부터 10분 안에 페이지에 반영된다.
- 몇 군 판정은 **경기 시작 6시간 전 ~ 시작 후 4시간** 사이 경기만 한다 (목록엔 전부 나옴).
- 깃허브 예약 실행은 붐비는 시간에 몇 분씩 밀릴 수 있다.
- 저장소에 60일 동안 사람 손길이 없으면 깃허브가 예약 실행을 멈출 수 있다. 그러면 깃허브에서 메일이 오니 Actions 탭에서 다시 켜면 된다.
- 링크를 모르는 사람은 들어올 일이 없지만, Public 저장소라 주소를 알면 누구나 볼 수는 있다.

## 손볼 일이 생기면

- **리그 추가·삭제**: `config.json`을 고친다. slug는 ESPN 기준(`eng.1`, `esp.1`, `uefa.champions` …).
- **slug가 살아 있는지 확인**: 로컬에서 `pip install requests` 후
  ```
  python collect.py --check-leagues
  ```
  리그별로 `O` / `X`와 최근 5일 경기 수를 찍어준다. `X`가 나오면 그 줄을 `config.json`에서 빼면 된다.
- **판정 기준 변경**: `grade.py`의 `GRADE_CUTS`(1군/1.5군 인원 기준), `HISTORY_MATCHES`(최근 몇 경기로 볼지, `collect.py`).
- **테스트**: `python tests/test_grade.py`, `python tests/test_parse.py`, `python tests/test_collect.py` — 네트워크 없이 돈다.

## 화면에 나오는 것

**목록**
- 필터: 전체 · 관심(★) · 전력 차 큼(전력 60 vs 40 이상, 전력 비교가 없는 야구는 등급 차이) · A매치 · 종목별
- 경기마다 양 팀 등급과 "전력 49 vs 51", 발표 전이면 예상 발표 시각. 누가 빠졌는지·에이스 여부는 눌러서 상세에서
- ★를 누르면 관심 경기로 맨 위에 고정 (이 폰에만 저장)

**상세**
- 전광판: 양 팀 등급, 시즌 성적, 주전 수·전력 보존율 막대, 자동 한 줄 요약
- LINEUP POWER · 오늘 라인업 전력: 1군/2군과 별개로 **오늘 선발끼리** 비교 ("레알 2군이 헤타페 1군보다 셀 수도 있다"를 판단)
  - 오늘 전력 49 : 51 + 판정(비슷한 전력 / 근소 우위 / 우위)과 이유 한 줄. 승률이 아니라 라인업 무게 비교
  - 계산 근거: 팀 체급(리그 경기당 승점, 경기 수 적으면 평균 쪽 보정) × 라인업 계수(전력 보존율 60% + 오늘 선발 득점·도움 지분 40%)
  - 오늘 선발 11명 시즌 합산(골·도움·출전시간·선발 경험·뛴 경기 승점), 오늘 선발 최다 득점·도움, 팀 최다 득점자가 빠졌는지
  - 라인별 비교: 공격진·미드필드 골+도움, 수비·골키퍼 선발 시 경기당 실점
  - 챔스처럼 리그가 다른 팀끼리는 각 팀 자국 리그 기록을 자동으로 찾아 쓰고, `config.json`의 `league_strength`(리그 수준 보정, 추정치)를 적용
- ACE · 팀 에이스: 시즌 기록 50% + 최근 6경기 50%로 팀마다 1명. 선발·벤치·명단 제외 중 어디인지 표시, 에이스가 빠지면 빨간 테두리
- 핵심 포인트 3줄, 한 경기장에 양 팀 포메이션
- 전력 비교: 가운데 기준 양쪽 막대 (자기 막대가 길수록 전력 온전) — 주전 선발·전력 보존율·득점 지분·도움 지분·최근 5경기
- 빠진 주전: 벤치/명단 제외, 시즌 골·도움, 팀 득점 중 비중
- 선발·교체 명단: **숫자는 시즌 전체**(출전·시간·골·도움), 이름 아래는 **최근 분위기**
  - 분위기 칩 하나: ▲ 상승세 / ▼ 하락세 / ● 공격 감각 / ━ 꾸준 / ◐ 들쭉날쭉 / ○ 출전 적음
  - 최근 5경기 칸: 파랑 "선" 선발 · 노랑 "교" 교체 · 어두운 빨강 "–" 미출전, 노란 점 = 골·도움 (오른쪽이 최신)
  - 에이스 행은 ACE 태그와 노란 배경, 누르면 경기별 기록과 최근·시즌 비교
- 야구: 선발투수, 선발 타순, 팀 홈런·타점 1위

한 줄 요약과 핵심 포인트는 수집한 기록으로 자동 작성한다. 데이터에 없는 내용은 만들지 않는다.
출전시간은 교체 시각으로 계산하고(90분 기준), 교체 시각을 못 받은 경기가 섞이면 "~"를 붙인다.

## 판정 방식

- 팀의 **최근 6경기 선발 명단**을 모아 선발 횟수가 많은 순으로 기준 인원(축구 11, 야구 9, 농구 5)을 뽑는다 → 이게 "주전".
- 오늘 선발 중 주전이 몇 명인지로 등급을 매긴다. 축구 기준 9명 이상 1군, 6~8명 1.5군, 5명 이하 2군.
- 선수별 분류: 최근 6경기 중 선발 60% 이상 주전 / 30~60% 로테이션 / 그 미만 백업 / 기록 없으면 신규·복귀.
- 야구는 선발 횟수 대신 **시즌 타석 ÷ 팀 경기 수**로 주전을 가린다(경기당 2.2타석 이상). 선발투수는 따로 표시.
- 최근 기록이 3경기 미만이면 "판단불가"로 둔다. 억지로 판정하지 않는다.

## 안 되는 것 (알고 쓰기)

- **K리그·아시안게임·대표팀 대회**: `config.json`에 후보를 넣어뒀지만, ESPN이 일정만 주고 라인업은 안 주는 리그도 있다. `소스 점검` 워크플로를 한 번 돌리면 리그별로 "라인업 있음 ★ / 라인업 없음"이 찍힌다. 없는 리그는 목록에만 뜨고 몇 군 판정은 비게 된다.
- **KOVO(배구)·KBO·KBL**: 공개 API가 없다. KBO는 공식 사이트 `robots.txt`가 데이터 경로(`/ws/`)를 막아둬서 자동 수집이 규약 위반이고, 게임센터·KOVO 모두 브라우저로 렌더링해야 라인업이 보인다. 네이버 스포츠 경유가 유일한 현실적 통로라 `probe.py`에서 접근 가능 여부를 같이 찍는다.
- **ESPN 피드는 비공식**이다. 구조가 바뀌면 깨질 수 있어서, 값이 없으면 "자료 없음"으로 떨어지게 짰다. 요청도 10분 간격·상한 500건으로 묶어뒀다.
- **유럽 축구 야간 경기**: 라인업은 킥오프 1시간 전에 나온다. 배트맨은 22시 이후 구매가 안 되니, 23시 이후 시작 경기는 사고 나서 확인하는 용도가 된다.

## 소스 점검 (설치 직후 한 번)

`Actions → 소스 점검 → Run workflow`를 누르면 로그에 이렇게 찍힌다.

```
O  kor.1   K리그1   ±7일 경기 12개 / 라인업 있음 (선발 22명 확인) ★
△  asian.games  아시안게임(후보 A)  응답은 되지만 ±7일 경기 0개
O  네이버 배구 일정  경기 4개 / 대회: V-리그
```

- `★`가 붙은 리그는 몇 군 판정까지 완전히 돌아간다.
- `X`는 slug가 없는 것이니 `config.json`에서 빼면 된다.
- 네이버 줄이 `O`로 나오면 K리그·KBO·KBL·KOVO도 붙일 수 있다.

## A매치 (국가대표)

- 친선전·월드컵/유로 예선·네이션스리그·본선(월드컵·유로·아시안컵·코파·골드컵·아프리카컵)과 여자 A매치를 `config.json`에 넣어뒀다 (`"national": true`). 목록 필터에 **A매치** 칩이 생긴다.
- 대표팀은 시즌이 없어서 친선·예선·본선 기록을 날짜순으로 합쳐 **최근 A매치 최대 20경기**를 "대표팀 기록"으로 쓴다 (화면 문구도 "시즌" 대신 "대표팀").
- 전력 비교는 **World Football Elo(eloratings.net)** 대표팀 레이팅을 쓴다. 로테이션만큼 Elo를 깎고(완전 2군이면 −200), 친선전·예선은 홈팀에 +100. 결과는 Elo 기대 성적(무승부는 절반) 비율이라 승률과 다르다.
- eloratings.net은 남자 대표팀만 있어서 **여자 A매치는 라인업 분석(몇 군·에이스·분위기)까지만** 나오고 Elo 전력 비교는 빠진다.
- ESPN에 아시안게임 대회가 없으면 아시안게임 경기는 목록에 안 나온다 (`소스 점검`으로 확인).
- 강도 조절: `grade.py`의 `ELO_ROTATION`(로테이션 감점), `ELO_HOME`(홈 이점), `collect.py`의 `NATIONAL_MATCHES`(모을 A매치 수), `config.json`의 `home_advantage_slugs`(홈 이점을 줄 대회).

## 예측 기록장 (archive 폴더)

라인업이 나온 경기는 **경기 시작 전 판정**(몇 군·주전 수·보존율·오늘 전력·Elo·에이스·선발 명단)을
`archive/2026-09.jsonl`처럼 월별 파일에 한 줄씩 저장하고, 경기가 끝나면 **실제 점수와 결과**를 같은 줄에 채운다.

- 화면용 데이터(`docs/data`)는 3일 지나면 지워지지만 기록장은 **지워지지 않고 계속 쌓인다**.
- 시작 전까지는 라인업 변동을 반영해 계속 갱신하고, 시작 후에는 판정을 고치지 않는다 (나중에 결과를 보고 판정을 바꾸는 착시 방지).
- 쌓인 기록으로 나중에 **점수 방식 백테스트**(60 vs 40이라고 한 경기에서 실제로 얼마나 이겼는지, 어떤 강도 값이 가장 잘 맞는지)를 할 수 있다.
- 파일은 저장소의 `archive` 폴더에서 바로 볼 수 있고, 통째로 받아서 Claude에게 올리면 분석해 줄 수 있다.

## 데이터를 일부러 안 쓰는 것

- **ClubElo(클럽 Elo 점수)**: 사이트가 자동 접근을 금지(robots.txt)하고 API 서버도 불안정해 쓰지 않는다. 체급은 ESPN 경기 결과로 직접 계산한다.
- **컵대회 기록**: 상대가 약해 2군 선수 성적이 부풀려지므로 선수·팀 성적은 리그 경기만 쓴다.
